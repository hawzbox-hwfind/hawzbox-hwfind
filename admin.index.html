How Professional Apps Manage — Honest Guide

1. Live DB, Not localStorage

Your app already uses Supabase posts table live. Admin dashboard uses SAME table. When you delete in admin, it deletes in app instantly. That's professional.

2. Paystack Webhooks

Don't check payment in frontend only. Create Paystack webhook URL → Supabase Edge Function → inserts into payments table with reference, amount, type (view/post), user_id, verified=true. App checks payments table before showing contacts or allowing post.

3. Feature Flags

admin_settings table with 1 row: pay_to_view_enabled, pay_to_view_amount, pay_to_post_enabled, pay_to_post_amount, paystack_public_key. App fetches on load. You toggle here, app respects instantly. No deploy needed.

RECOMMENDED SUPABASE TABLES SQL (Run in Supabase SQL Editor):

-- Admin settings (single row)
create table admin_settings (
 id int primary key default 1,
 pay_to_view_enabled boolean default true,
 pay_to_view_amount int default 500,
 pay_to_post_enabled boolean default false,
 pay_to_post_amount int default 1000,
 paystack_public_key text default 'pk_test_...',
 paystack_secret_key text default 'sk_test_...',
 updated_at timestamp default now()
);
insert into admin_settings (id) values (1) on conflict (id) do nothing;

-- Payments
create table payments (
 id uuid primary key default gen_random_uuid(),
 reference text unique,
 email text,
 amount int,
 type text, -- 'view_contact' or 'post_house'
 post_id text,
 user_id text,
 status text default 'success',
 created_at timestamp default now()
);

-- Broadcasts
create table broadcasts (
 id uuid primary key default gen_random_uuid(),
 title text,
 message text,
 target_user_id text, -- null = all users
 created_at timestamp default now()
);

-- Enable RLS and allow anon (for demo, secure later with policies)
alter table admin_settings enable row level security;
alter table payments enable row level security;
alter table broadcasts enable row level security;
create policy "allow all" on admin_settings for all using (true) with check (true);
create policy "allow all" on payments for all using (true) with check (true);
create policy "allow all" on broadcasts for all using (true) with check (true);
